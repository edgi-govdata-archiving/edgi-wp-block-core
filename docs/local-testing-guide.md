# Local Sandbox Testing Guide

Developing blocks directly in WordPress can slow down the feedback loop due to database synchronization, page reloads, and PHP loading processes. This document details how to test frontend scripts and styling in a local sandbox environment.

---

## 1. Why Sandbox Testing is Necessary

Our interactive blocks load large geographical boundaries (JSON) and custom metadata (CSV) asynchronously via the browser's Fetch API (`d3.json` and `d3.csv`).

If you open the static sandbox HTML file directly in your browser (`file://` protocol), the browser will block these requests due to **strict CORS security policies**.

To solve this, we run a lightweight, zero-dependency development server locally to serve files over `http://localhost`.

---

## 2. High-Speed Local Dev Sandbox Workflow

Follow these steps to test your block with sub-second reload speeds:

### Step 1: Run the Webpack Compiler

In your main terminal, start the compiler watcher. This will rebuild your block assets immediately whenever you save changes to your SCSS or JS files:

```bash
npm run start
```

### Step 2: Start the Dev Server

Open a separate terminal window at the root of the plugin directory and start the local development server:

```bash
npm run serve
```

_Note: This command runs the script at `bin/serve.js` on port `8080`._

### Step 3: Open the Sandbox Page

Open your browser and navigate to your sandbox file in the gitignored `sandbox/` directory:
[**`http://localhost:8080/sandbox/test-sandbox.html`**](http://localhost:8080/sandbox/test-sandbox.html)

---

## 3. How the Sandbox is Configured

The sandbox is powered by two files:

### A. The HTML Sandbox Wrapper (`sandbox/test-sandbox.html`)

This file is a simple, lightweight HTML outline placed in the `sandbox/` directory. You probably won't see any files in `sandbox/` by default, because the directory is gitignored. You can create a file yourself to test various page layouts for your block. This file replicates the DOM elements generated by the WordPress PHP render callback:

```html
<div
  class="edgi-visualization-dashboard"
  data-csv-url="../assets/report-metadata.csv"
  data-states-json-url="../assets/maps/us-states.json"
  data-districts-json-url="../assets/maps/cb_2025_us_cd119_5m.json"
>
  <div class="edgi-map-container">
    <!-- Structural layouts for canvas, sidebars, and details panel -->
  </div>
</div>

<link
  rel="stylesheet"
  href="../build/congressional-report-cards/style-index.css"
/>
<script src="../build/congressional-report-cards/view.js"></script>
```

### B. The Dev Server (`bin/serve.js`)

A global Node.js server that enqueues the appropriate CORS headers and mime-types (`.css`, `.js`, `.json`, `.csv`, `.png`, etc.) for local resources, allowing high-speed local testing without database overhead or CORS security blockages.
